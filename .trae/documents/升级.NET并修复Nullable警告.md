# 升级 .NET 版本并修复 Nullable 警告计划

## 任务概述

将项目从 .NET 6 升级到 .NET 8/9，并使用 C# 11+ 特性修复 132 个 Nullable 引用类型警告。

## 当前状态分析

* **当前版本**: .NET 6.0-windows (net6.0-windows)

* **C# 版本**: C# 10 (隐式)

* **警告数量**: 132 个

* **警告类型**: 主要为 CS8618（未初始化的不可为 null 字段）

## 实施步骤

### 步骤 1：创建新分支

```bash
git checkout -b feature/nullable-warnings-fix
```

### 步骤 2：升级 .NET 版本

* 修改 `jsxbin_to_jsx_GUI.csproj`

* 将 `<TargetFramework>net6.0-windows</TargetFramework>` 改为 `net8.0-windows` 或 `net9.0-windows`

* 确保项目兼容性

### 步骤 3：分析并修复警告

根据警告类型分为三类：

#### 3.1 修复 CS8618 警告（115 个）

**类型**: 不可为 null 的字段未初始化

**解决方案**: 使用 C# 11+ 的 `required` 修饰符

**处理策略**:

1. **识别需要 required 的字段**：找出所有 Node 类中声明但未初始化的字段

2. **添加 required 修饰符**：

   ```csharp
   // 修改前
   public class ForStatement : AbstractNode
   {
       ForStatementInfo bodyInfo;
       ForStatementInfo loopVarInfo;
   }

   // 修改后
   public class ForStatement : AbstractNode
   {
       public required ForStatementInfo bodyInfo;
       public required ForStatementInfo loopVarInfo;
   }
   ```

3. **受影响文件**：50+ 个 Node 类文件

#### 3.2 修复 CS8600/CS8602/CS8603 警告（17 个）

**类型**: 可空引用操作警告

**位置**:

* `AbstractNode.cs`: 134, 135, 150, 155, 159, 170, 218, 350 行

* `SymbolTable.cs`: 14 行

**解决方案**: 使用 null 检查或适当的可空注解

**示例**:

```csharp
// 修改前
return table.TryGetValue(key, out var value) ? value : null;

// 修改后 - 使用 ! 操作符明确表示已知非空
if (table.TryGetValue(key, out var value))
    return value;
return null;
```

#### 3.3 修复其他属性警告

**位置**:

* `BinaryExpr.cs`: 6 个属性

* `ConstDeclarationInfo.cs`: 4 个属性

**解决方案**: 使用 `required` 或添加 `= null!;`
